## NuGet 发布

发布使用 **Trusted Publishing**（GitHub OIDC，无长期 API Key）：

1. nuget.org → 受信任的发布 → 策略：`WenLiu197 / PhiLibrary197 / publish.yml`
2. GitHub Secrets：`NUGET_USER` = nuget.org 用户名
3. 在 release 分支完成版本号和 CHANGELOG 后打 tag：

```bash
git tag v1.0.0
git push origin v1.0.0
```

workflow（`.github/workflows/publish.yml`）会构建 slnx，用 OIDC 换取临时密钥并 `dotnet nuget push`。

## 分支与 PR 流程

- 功能/修复从最新 `master` 开分支：

```bash
git switch master
git pull --ff-only origin master
git switch -c feature/xxx
```

- 本地完成构建和测试后提交、推送；
- 用 `gh pr create` 创建 PR：
  - Assignee：`WenLiu197`
  - Label：`bug` / `enhancement` / `refactor` 之一
  - Milestone：有匹配版本时选择一个；仓库没有 milestone 时留空
- 等 CI 通过，远程合并后拉取 master；
- 删除已合并的本地/远程分支；
- 发布/文档/版本/CHANGELOG 等工作在 `release/vX.Y.Z` 分支完成。
